# cutline

An EDL-based video pipeline. Deterministic Python core, agent-drivable.

`cutline` removes dead air from talking-head video and produces a verified MP4. It is built
around a single intermediate representation — an **edit decision list** — so that every
capability is either a producer or a consumer of that one artifact.

```
   [producers]              [the seam]            [consumers]

 silence analysis ──┐                         ┌──→ render  (ffmpeg)
 transcript   (v2) ─┼──→    EDL (JSON)   ─────┼──→ captions (v2)
 human editor (v3) ─┘       keep-segments     └──→ probe / report
```

## Status

**v0.1.0 — in development.** The design is specified in
[`docs/specs/2026-08-22-cutline-v1-design.md`](docs/specs/2026-08-22-cutline-v1-design.md).

## Why an EDL

Most media tools couple analysis to rendering: a function takes an MP4 and returns an MP4,
and the decisions it made are lost. That makes the interesting part — *what got cut and
why* — invisible and untestable.

`cutline` writes those decisions down:

```json
{
  "source": "raw.mp4",
  "duration": 612.4,
  "keeps": [
    { "start": 0.0,  "end": 12.3 },
    { "start": 14.9, "end": 31.2 }
  ]
}
```

The EDL is inspectable, diffable, hand-editable, and trivial to assert on in a test. Adding a
new way to decide cuts means adding a producer. Adding a new output means adding a consumer.
Neither touches the other.

## Requirements

- Python ≥ 3.12 (managed by [uv](https://docs.astral.sh/uv/); your system Python is untouched)
- `ffmpeg` and `ffprobe` on `PATH`

## Verification

`cutline` does not report success from a subprocess exit code. A render is verified by
probing the artifact it produced — duration, stream count, frame count, codec — and the
test suite asserts on that probe rather than on mocks.

Test fixtures are **generated by ffmpeg at test time**, never committed, so the repository
stays text-only and the tests stay hermetic.
